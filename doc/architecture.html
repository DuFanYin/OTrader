Optra

Architecture

An options trading system: one engine for backtest and live, one server for the page and agents, and a research loop that counts every try.

Cut at gRPC: the control plane asks, the core owns the trading state and reaches the world through adapters.

  • control plane: asks and shows
  • core: owns the trading state
  • adapters: the outside world
  • quant: the numerics

Every try is registered before it runs, judged against luck and a random-buying control, and promoted only on evidence in the ledger; the person approves anything that trades.

  • data: checked, one format
  • control plane: the steps and gates
  • core: the engine
  • quant: the statistics
  • not built yet

One process, the code a backtest runs. Only the event thread changes trading state, one event after another; the network, the disk and the log each have a thread of their own.

  • adapters: the threads facing outside
  • core: owns the trading state
  • control plane: the server's commands
  • quant: the numerics

The live engine's code, replayed a minute at a time. A day is read and priced once for all its trials, cached as it is read, and every result is summed in one place.

  • data: three tiers, nothing lost
  • core: the batch engine
  • control plane: jobs, ledger, the sums
  • quant: the pricing
